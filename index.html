Request

“작업 절차가 서식 · 무전 · 현장 조치로 흩어져 있어, 신입이 순서대로 익힐 수 있는 훈련이 필요해요.”

“실제 서식도 그대로 작성해 보고, 열차 접근 대응도 반복해서 연습할 수 있게 해 주세요.”

Direction

디자인 방향

  • 단계 카드 + 잠금 — 현장 점검 · 입문 · 실습 · 평가를 카드로 나누고 순서를 잠금으로 지키게 했습니다.
  • 서식 하이라이트 안내 — 실제 서식을 팝업으로 띄우고 지금 채울 칸을 하이라이트와 자막으로 안내했습니다.
  • Unity 리소스 체계 — 9-slice와 네이밍 규칙(ui_btn_ · ui_bg_ · ui_img_)으로 개발 전달용 리소스를 정리했습니다.

/01—Overview

선로 작업자가 작업 전·중·후에 거치는 안전 절차를 PC에서 순서대로 실습하는 훈련 프로그램입니다. 절차가 서식·무전·현장 조치로 흩어져 있어 신입이 익히기 어렵다는 요청에서 출발해, 실제 현장 서식(작업계획서·운행안전협의서·적합성검사기록부) 작성과 무전 협의, 열차접근 대응까지 하나의 흐름 안에서 반복하도록 구성했습니다. 기획 2명, 개발 1명, 3D 2명과 함께하며 UI를 단독으로 디자인했고 Unity 리소스 체계까지 정리했습니다.

Main

훈련 단계 선택

메인은 학습자가 지금 어느 단계를 해야 하는지 판단하는 화면입니다. 현장 점검·입문·실습·평가 단계를 카드로 나눠 나란히 두고, 아직 열리지 않은 단계에는 잠금 안내를 붙였습니다. 순서를 건너뛰면 신입이 절차를 차례로 익힌다는 목적이 흐려지기 때문에 앞 단계를 마쳐야 다음 카드가 열리게 했습니다. 조작 안내는 최초 진입 때만 띄우고 이후에는 인포 버튼으로 다시 열게 해 반복 훈련의 흐름을 끊지 않았습니다.

Document

서식 작성

실제 서식을 그대로 작성해 보는 훈련이 요청에 있었기 때문에 작업계획서 양식을 바꾸지 않고 팝업에 그대로 띄웠습니다. 칸이 많은 양식에서 어디부터 써야 할지 헤매지 않도록 지금 채울 칸만 하이라이트하고, 같은 내용을 하단 자막으로 한 번 더 안내했습니다. 운행안전협의서는 ①~⑦을 작성한 뒤 무전 협의를 거쳐 ⑧을 채우는 순서까지 실제 절차에 맞췄습니다.

Radio

무전 협의

작업승인번호 수령, 작업시작 승인, 작업종료 보고처럼 절차 곳곳에 무전 협의가 들어갑니다. 철도운행안전관리자와 운전취급책임자 사이의 대화를 말풍선으로 순서대로 쌓아 누가 먼저 무엇을 말하는지 대화 흐름 그대로 따라가게 했습니다. 무선전화기와 무전 애니메이션을 함께 보여 주어, 서식 작성과 현장 조치 사이에서 무전이 어느 시점에 오는지를 절차 안에서 익히도록 했습니다.

Complete

수료 요약

철수와 작업종료 보고까지 마치면 수료 요약 카드로 단계 완료를 알립니다. 확인을 누르면 메인으로 돌아가고, 방금 마친 단계 다음 카드가 열리도록 연결했습니다. 한 단계의 끝이 다음 단계의 시작으로 바로 이어지게 해, 메인의 단계 카드와 잠금으로 만든 순차 학습 구조가 수료 화면에서 매듭지어지도록 했습니다.

서비스 엔지니어가 XR 헤드셋에서 냉장고 수리 과정을 실습하는 교육 콘텐츠입니다. 냉장고 실물을 계속 뜯거나 고장 상황을 일부러 만들 수 없다는 제약을 XR로 풀어, 실수가 잦은 작업을 보호구 착용과 필수안전수칙부터 진단기(HASS) 연결, 배관 작업, 락슬리브 압착까지 실제 순서대로 반복하게 했습니다. 시안 3개로 방향을 맞춘 뒤 삼성 브랜드 블루를 살린 전문적인 톤과 헤드셋 가독성 기준으로 UI를 단독 디자인했습니다.

Lobby

로비

로비는 훈련을 시작하기 전에 머무는 공간이자 튜토리얼로 넘어가는 출발점입니다. 보호구와 장비를 눈앞에 배치해 무엇을 착용하고 시작하는지를 패널을 읽기 전에 먼저 보이게 했습니다. 패널은 Comfortable Zone·Safety Zone 기준으로 크기와 거리를 잡아 고개를 크게 돌리지 않고 읽히게 했고, 이후 보호구 착용 안내와 필수안전수칙 01~04로 자연스럽게 이어지도록 했습니다.

HASS

진단기 모니터링

냉장고 수리는 진단기(HASS)로 상태를 확인하는 데서 시작합니다. 진단기 화면을 실습 공간 안에 태블릿 패널로 띄워 연결, 에러 이력, 약냉 진단, 테스트 모드, 모니터링까지 같은 자리에서 확인하게 했습니다. 상태 값이 많은 화면이라 XR 특유의 가독성 문제를 고려해 헤드셋 기준으로 글자와 수치 크기를 잡았고, 진단을 마치면 바로 배관 작업으로 넘어가도록 작업 흐름 안에 배치했습니다.

Caution

작업주의사항

각 훈련은 본 작업 전에 전동툴·실란트·락링 주의사항을 먼저 보여 주는 순서로 짰습니다. 락슬리브 삽입 방향처럼 틀리기 쉬운 지점은 작업주의사항 패널 설명에 그치지 않고 손이 가야 할 위치를 공간 안에서 직접 하이라이트했습니다. 패널을 읽고 다시 부품을 찾는 시선 이동을 줄이고, 실수가 잦은 동작을 손 위치와 함께 반복해 익히도록 하려는 결정이었습니다.

/01—Overview

특수선 정비 인력이 Galaxy Tab S8 Ultra에서 기술교범을 찾아보는 앱입니다. 종이·PDF 교범이 너무 많아 현장에서 필요한 장비 정보를 찾기 어렵고 문서만으로는 장비가 배의 어디에 있는지 알 수 없다는 문제를, 3단계 드릴다운과 콘텐츠 유형별 뷰어(텍스트·PDF·영상·파노라마·3D CAD·3D 애니메이션)로 태블릿 하나에 모았습니다. 국가보안 문제로 3D는 고객사가 맡았고, 태블릿 터치 기준과 계통 색상 구분을 원칙으로 UI를 단독 디자인했습니다.

3D Animation

3D 애니메이션

3D 애니메이션은 장비의 구조와 작동을 움직임으로 보여 주는 뷰어입니다. 부품이 어떤 순서로 맞물려 움직이는지는 텍스트나 PDF만으로 이해하기 어려워, 같은 교범 항목 안에서 장비를 애니메이션으로 재생해 문서를 보완하게 했습니다. 어느 콘텐츠에서든 햄버거 버튼과 트리 목차로 다른 유형의 콘텐츠로 이동할 수 있게 해, 애니메이션을 보다가 관련 문서로 바로 돌아갈 수 있도록 했습니다.

Drill-down

드릴다운 목록

메인은 방대한 교범 중 원하는 항목을 찾아 들어가는 출발점입니다. Level 1~3 카테고리를 단계별 열로 나란히 펼쳐 계통에서 장비로 범위를 좁혀 가게 했고, 앞 단계의 선택이 화면에 남아 지금 어느 계통의 어느 장비를 보고 있는지 놓치지 않게 했습니다. 목록 행은 태블릿 터치 기준으로 크기를 잡고 계통마다 색을 달리해, 항목이 많아도 소속을 빠르게 구분하도록 했습니다.

3D CAD

3D CAD 콘텐츠

문서만으로는 장비가 배의 어디에 있는지 알 수 없다는 요청에 답하는 화면입니다. 함정 구획을 3D로 띄우고 Deck·Room·장비 라벨을 붙였으며, Deck 단위로 층을 옮겨 가며 내부에 접근하게 했습니다. 시점 조작은 3D Control Bar에 모아 터치로 다루게 해, 교범에서 읽은 장비를 실제 배 구조 위에서 바로 찾아볼 수 있도록 했습니다.

Panorama

파노라마 콘텐츠

파노라마는 구획 내부를 360°로 둘러보며 장비를 찾는 화면입니다. 파노라마 위에 장비 라벨을 계통별로 띄우고 계통 필터로 필요한 것만 남기게 했으며, 미니맵을 겹쳐 지금 배의 어느 위치를 보고 있는지 알 수 있게 했습니다. 최소화 상태도 따로 두어 화면을 넓게 쓰면서 공간 안에서 장비 위치를 바로 확인하도록 했습니다.

/01—Overview

중소조선연구원 생산기술혁신(DX)센터 실험동을 3D 디지털 트윈으로 옮겨, 센터 전경(Lv1) → 건물(Lv2) → 층(Lv3) → 장비(Lv4) 순서로 범위를 좁혀 가며 설비 가동·CCTV·센서 데이터를 한 화면에서 관제하게 한 프로젝트입니다. 실험동 현황을 한 화면에서 보고 싶다는 요청에 맞춰 좌측 지표·우측 CCTV 고정 구조와 글래스 딥블루 톤, AI 에이전트 챗봇을 설계했습니다. 개발 담당자가 여러 번 바뀌며 UI 스타일과 개발 방향이 여러 차례 조정되는 가운데 UI를 단독으로 디자인했습니다.

Lv1 · Main

센터 전경

센터 전체를 3D로 보여 주는 첫 화면이자 관제의 출발점입니다. 전경 위에 정보를 많이 얹기보다 건물 배치가 먼저 읽히게 하고, 상단에는 알림과 사용자 메뉴만 두어 업데이트와 경고를 바로 확인하게 했습니다. 알림은 다이얼로그와 토스트로 나눠 정의했고, 사용자 메뉴는 드롭다운에서 My Page로 이어지게 했습니다.

Lv2 · Building

건물 선택

관제할 건물을 고르는 단계입니다. 건물을 고르면 해당 동이 3D 위에서 하이라이트되어 선택이 공간에서 바로 확인되고, 이어서 층별 관제로 들어갑니다. 목록에서 이름을 고르는 대신 실제 배치 위에서 고르게 해, 실험동의 위치 관계를 익힌 상태로 다음 단계에 진입하도록 했습니다.

Lv3 · Floor

층별 관제

설비 가동 현황과 CCTV·센서를 한 화면에서 보고 싶다는 요청에 가장 직접 답하는 화면입니다. 좌측에 실시간 관제 현황(가동률·이상 발생·IoT 온도), 우측에 CCTV와 장비 상태를 고정하고 가운데에 실험동 설비를 두어, 지표와 영상이 늘 같은 자리에 있도록 했습니다. CCTV는 송신 오류 상태까지 정의했고, AI 에이전트 대응 가이드와 패널 최소화 상태도 함께 설계했습니다.

Lv3 · Detail

장비 상세 패널

가운데 3D에서 설비를 고르면 장비 정보 패널이 해당 설비 옆에 떠 상태와 가동 정보를 보여 줍니다. 좌우 고정 패널에 정보를 더 쌓는 대신 선택한 설비 가까이에 띄워, 어느 장비의 정보인지 위치로 바로 연결되게 했습니다. 여기서 장비를 선택하면 장비 단위의 Lv4 실시간 데이터로 이어집니다.

Lv4 · Equipment

실시간 데이터 (MIG / TIG)

Lv4는 MIG·TIG 용접 장비 하나를 들여다보는 단계입니다. 실시간 데이터와 제품 현황, 작업 모니터를 한 화면에 함께 두어 장비가 지금 어떤 값으로 돌아가고 무엇을 만들고 있는지 화면을 오가지 않고 확인하게 했습니다. 용접 장비의 정상·이상 상태는 상태 인디케이터로 따로 표시해, 데이터를 다 읽기 전에 이상 여부부터 알아보게 했습니다.

Lv4 · Unit

유닛 정보 카드

장비 모델 위에 부품 스팟을 두고, 스팟에 마우스를 올리면 유닛 정보 카드가 떠 정상·이상 상태를 바로 구분하게 했습니다. 카드는 호버와 선택 상태를 나눠 정의하고 부품 정보는 Parts 카드로 따로 정리했습니다. 가볍게 훑는 정보와 골라서 보는 정보를 나눠, 3D 모델을 가리는 패널을 최소화하려는 결정이었습니다.

Screens

상태별 화면

로그인부터 알림, 설비 상태 표시, 패널 최소화, 장비 카드까지 관제 화면의 상태입니다.

/01—Overview

KTX 차량을 대상으로 설계·운영·시뮬레이션 데이터를 하나의 3D 모델 위에서 연결하는 철도차량 디지털 트윈입니다. 대차프레임 같은 부품의 센서·구조해석 데이터로 상태를 보고 예측하고, 시뮬레이션과 실제 주행 영상을 맞춰 보고 싶다는 요청에 따라 차량을 먼저 고른 뒤 영역을 전환하는 구조로 설계했습니다. 구조 트리와 정보 패널을 3D 모델 양옆에 고정하고 KRRI 브랜드 톤을 적용했으며, 기획·개발·3D 각 1명과 함께 UI를 단독으로 디자인했습니다.

Gateway

차량 시스템 선택

KTX-청룡·산천·이음 중 대상 차량을 먼저 고르고 진입하는 첫 화면입니다. 설계·운영·시뮬레이션 데이터가 모두 차량의 3D 모델에 묶여 있기 때문에 차량 선택을 맨 앞에 두어, 이후 모든 영역이 같은 차량을 기준으로 열리게 했습니다. 진입한 뒤에는 영역만 전환하도록 흐름을 나눠 같은 부품을 여러 관점으로 이어서 볼 수 있게 했습니다.

Design

설계 영역

설계 영역은 부품의 설계 정보를 확인하는 화면입니다. 구조 트리와 부품 정보·설계 변경 이력 패널을 3D 모델 양옆에 배치해, 트리에서 대차프레임 같은 부품을 고르면 옆 패널이 그 부품을 기준으로 채워지게 했습니다. 트리와 패널을 양옆에 고정한 것은 영역을 바꿔도 같은 자리에서 부품을 고르고 정보를 읽게 하기 위해서였습니다.

Operation

운영 영역 · 실시간 센서

운영 영역은 선택한 부품의 실시간 센서 데이터를 보는 화면입니다. 센서 값을 그래프로 보여 주고 계측 방향과 기간을 바꿔 볼 수 있게 해, 같은 부품의 상태를 여러 조건으로 비교하게 했습니다. 설계 영역과 같은 트리·패널 구조를 유지해 영역이 바뀌어도 레이아웃을 다시 익히지 않고 데이터에 집중하도록 했습니다.

Simulation

시뮬레이션 결과 조회

시뮬레이션 영역은 구조해석 결과와 동특성 데이터를 확인하는 화면입니다. 결과를 별도 차트로 떼어 내지 않고 3D 모델 위에 겹쳐 보여 주어 어느 부위에 어떤 결과가 나왔는지 형상과 함께 읽히게 했습니다. 타임라인으로 시나리오를 재생하게 해, 시간 흐름에 따라 결과가 어떻게 달라지는지 따라갈 수 있도록 했습니다.

/01—Overview

LNG선의 화물·배관 시스템을 3D로 이해하고, 장비별 매뉴얼·도면·설명을 한 화면에서 찾고, 운항 중 장비 데이터를 디지털 트윈 위에서 모니터링하는 HD 한국조선해양의 XR 콘텐츠 HiDTS입니다. 운항팀·교육생·유지보수 인력이 같은 환경에서 학습하고 진단하도록 좌측 내비게이션·우측 설명 구조와 도면·PDF·이미지 뷰어를 기본 틀로 잡았습니다. 2025 POC 이후 2026 1차에서 메인을 데이터 모니터링 중심으로 바꾸고 WebGL에서 PC로 옮기며 메뉴 구조를 개편했고, UI를 단독으로 디자인했습니다.

LNG 운반선은 수백 개의 탱크·밸브·펌프·배관이 얽힌 거대한 시스템입니다. 현장 인력이 이 구조를 익히려면 수개월의 도제식 학습이 필요했고, 안전 사고 대응 훈련도 실선에서는 사실상 불가능했습니다.

이 프로젝트는 그 격차를 메우는 작업이었습니다. 선체 외관부터 카고 핸들링 룸 내부의 밸브 한 개까지 모두 3D로 재현하고, 그 위에 실시간 데이터 스트림과 IGC·매뉴얼 문서를 얹었습니다.

풀어야 했던 문제는 명확했습니다. "무거운 정보를 가볍게 다루는 인터페이스" — 3D 뷰포트의 몰입감을 해치지 않으면서, 동시에 100개가 넘는 시그널과 컨트롤을 한 번에 접근할 수 있도록.

  • Top Bar — Persistent Context로고·홈·알림·시계가 어느 페이지에서도 같은 위치에 고정. 사용자의 위치 감각 유지.

Self-critique

돌아보기

잘된 결정들

  1. 선택적 무게 원칙3D 뷰포트와 2D UI가 충돌하지 않도록, 사용자 조작 영역만 고대비 카드로 두고 나머지는 글래스 처리. 3D 콘텐츠가 화면의 주인공으로 남아 인지 부하 감소.
  2. P&ID에 손대지 않은 결정디자이너 본능은 "정리해서 다시 그리자"였지만, 엔지니어가 평생 봐온 도면 형태를 유지한 것이 최선. UI 레이어만 새로 짜서 익숙함은 보존하고 가독성만 끌어올림.
  3. 6패널 데이터 모니터링 평행 그리드Cargo Tank, Steering, Gas Flow, Shaft, Navigation, Custody Transfer 여섯 카테고리를 동일 단위 카드로 정렬. 시선만 옮겨도 같은 위치에서 같은 종류 정보 검색 가능.
  4. 한·영 혼용 폰트 페어링Pretendard 단일 패밀리로 한글·영문·숫자 베이스라인 정렬. 시그널 ID(영문)와 부품명(한글)이 한 줄에 함께 나오는 화면에서 효과 컸음.

아쉬운 결정들

  1. 사이드바 트리의 깊이 한계현재 트리는 2-depth까지만 안정적. 한 탱크 아래 수십 개 부품을 펼치면 스크롤이 길어져 컨텍스트를 잃기 쉬움. breadcrumb + 가상 스크롤로 재설계 필요.
  2. 알림 UX의 비대칭상단바 노란 토스트로 알림 표시 — 우선순위·해제·이력 관리 없음. 실제 알람 동시 다발 시나리오 미반영 — 알림 센터를 별도 모듈로.
  3. 3D 뷰포트 접근성 한계키보드 only 사용자가 3D 모델을 탐색할 수단 부족. 스페이스로 라벨 토글 등 기본기는 있지만 미세 조작은 마우스 필수. 키보드/조이스틱도 동등 지원 필요.
  4. 다크 모드 부재관제 환경(브릿지)은 어두운 야간 운항이 길지만 라이트 톤만. 다크 모드는 단순 색반전이 아닌 P&ID 색 토큰 전반 재설계 필요 — 차기 버전 1순위.

Reflection

01

도메인을 모르면 디자인할 수 없다.

P&ID 기호를 외우고 LNG 화물 핸들링 절차를 읽는 데 첫 두 달을 썼습니다. 사용자의 언어를 빌려쓸 줄 모르면, 결국 사용자 모르는 화면을 만들게 됩니다.

02

시스템은 컴포넌트가 아니라 결정의 묶음이다.

진짜 시스템은 Figma 라이브러리가 아니라, "왜 이 결정을 했는가"를 기록한 룰북. 새 화면이 추가될 때마다 누군가 룰북을 펴 같은 답을 내릴 수 있어야 시스템이 살아남습니다.

03

XR은 화면이 아니라 환경이다.

2D 화면은 사각형 안의 위계를 고민하면 되지만, XR은 사용자가 카메라를 직접 움직임. "환경 자체의 일관성"을 보장해야 합니다.

/01—Overview

정비사가 장비 앞에서 태블릿으로 트러블슈팅 절차를 보며 고장을 진단하도록 돕는 현장 보조 AR 앱입니다. 신입 정비사·현장 교육생·서비스 엔지니어가 실장비 없이도 조작법·성능 테스트·부품 진단을 익히도록 현장 가독성을 고려한 큰 UI와 1~6 Depth 단계 안내를 설계했고, 두산에서 DEVELON으로 바뀐 브랜드를 반영했습니다. 2.0에서는 ENG·ELE·HYD 구성요소 재배치, 탑바 내비게이션, 와이어프레임 오버레이 구분, Report 정보 정리, 예외 처리와 전체 톤·메뉴 구조 개편을 진행했으며 UI를 단독으로 디자인했습니다.

건설중장비는 수만 개의 부품과 복잡한 ENG·ELE·HYD 시스템이 얽힌 거대한 기계입니다. 새로 입사한 정비사가 실제 굴착기를 손에 익히기까지 수개월의 OJT가 필요했고, 본사 외 지역 인력은 직접 만져볼 기회조차 제한적이었습니다.

이 프로젝트는 그 격차를 메우는 작업이었습니다. 굴착기 외형부터 엔진 룸 내부 센서까지 3D로 재현하고, 그 위에 회로 도면·부품 진단·성능 테스트 절차를 AR 가이드로 얹었습니다.

풀어야 했던 문제: 손에 들고 쓰는 도구로서 작동하는 인터페이스 — 태블릿 한 화면에서 3D 조작·시스템 선택·시뮬레이션을 한 번에, 그러나 한 번에 너무 많이 보여주지 않는 균형.

Reflection

01

손에 들고 쓰는 도구는 모서리가 적이다.

데스크탑 UI에선 자연스러운 "구석 액션 배치"가 태블릿에선 그립의 적이 됩니다. 사용자 손가락이 닿는지를 다시 한 번 측정했어야.

02

AR은 정보의 양보다 위치가 본질이다.

실장비 위에 텍스트를 띄우는 일은 쉽지만, 가려야 할 대상을 가리지 않도록 배치하는 일은 어렵습니다. 강조 박스의 크기·투명도·앵커링이 정확도보다 중요했습니다.

03

교육 콘텐츠는 사용자 단계를 가정해야 한다.

신입과 10년 차를 같은 화면으로 만족시키려 했지만, 정보 밀도·민감도·자막을 차등화하는 모드가 부족했습니다. "초급/숙련" 토글 한 줄이면 만족도가 훨씬 올랐을 것.

/01—Overview

실제 장비 없이 필터 교체·점검 주기 같은 정비 절차를 VR로 훈련하고, 교육을 마친 학습자가 경쟁사 장비와 사양을 직접 비교하도록 만든 Meta Quest 콘텐츠입니다. 중장비 현장 교육에 필요한 부지·건물·교육 전용 장비의 제약을 풀기 위해 정비 시뮬레이션(Part A)과 쇼룸(Part B)으로 구성했고, 손 거리 기준 UI와 안전 경고 최우선을 원칙으로 세웠습니다. 여러 디자이너와 함께 메인 UI를 맡았고, 2차에서 전체 톤과 메뉴 구조를 개편하고 콘텐츠를 추가하며 디자인 시스템을 정리했습니다.

중장비 정비 교육은 본래 실제 장비 + 정비사 + 안전관리자 + 작업 공간이 모두 필요합니다. 한 사람을 OJT로 키우기 위해 수개월의 라인이 묶이고, 사고 위험 때문에 신입은 단순 보조만 가능했습니다.

이 프로젝트는 그 비용 구조를 메타퀘스트로 옮기는 작업이었습니다. Part A는 정비 시뮬레이션 — 안전장구 착용부터 엔진 오일 교체, 필터 청소까지 손동작 기반으로 체험. Part B는 쇼룸 — 학습 종료 후 DEVELON 장비와 경쟁사(Caterpillar 등) 장비를 같은 공간에 배치해 치수·스펙을 직접 비교.

풀어야 했던 문제: VR 공간에서 떠다니는 UI — 데스크탑처럼 화면 모서리에 고정할 수 없고, 사용자가 머리를 돌릴 때마다 카드가 시야 밖으로 사라짐. 코너 컷 SVG 프레임 + 그리드 도트 백드롭으로 "실제 HUD 같은" 인상을 유지하되, 핵심 액션은 핸들바 같은 손 가까운 위치에 묶었습니다.

Primary Interface

Service Item Popup · Meta Quest · Part A 정비 시뮬레이션

Service Item 팝업은 정비 시뮬레이션에서 실제 작업을 고르고 실행하는 화면입니다. Category 드롭다운으로 같은 자리에서 카테고리를 바꾸고, Interval 정렬로 9999H 같은 큰 숫자의 정비 주기를 한 줄에 맞춰 비교하게 했습니다. 완료 체크는 VR 시야에서도 확실히 구분되도록 사이언 마름모로 만들고, 지금 진행할 수 없는 항목은 dim 처리했습니다. 뒤로가기는 작게 두어 모달 전체가 아니라 한 단계만 돌아가게 했습니다.

  • Back Action (←)상위 카테고리로 복귀. 코너 컷 프레임 안에 작게 — 모달 전체를 닫지 않고 한 단계만.
  • Category DropdownService Item ▼ — 현재 카테고리. 같은 위치에서 다른 카테고리로 빠르게 전환.
  • Complete Column완료 체크 영역. 체크 아이콘은 사이언 마름모로 — VR 시야에서도 확실히 식별되는 형태.
  • Interval ▼정비 주기 정렬. 9999H 같은 큰 숫자가 한 줄에 정렬되어 비교 용이.
  • Inactive Item진행 불가 항목은 dim 처리 — 사용자가 현재 단계에서 가능한 작업만 강조.
Worked well
  • 코너 컷 SVG 프레임 + 그리드 도트 백드롭으로 VR 공간에서 "실제 HUD" 인상 — 떠다니는 UI를 자연스럽게 정착
  • 체크 아이콘을 마름모 사이언으로 — VR 양안 시야에서도 또렷이 식별, 일반 ✓보다 가독성 우수
  • Interval 우측 정렬 + 큰 숫자(9999H)로 정비 주기 비교가 한 컬럼 안에서 즉시
Could be better
  • 리스트가 7-8개 항목만 표시 — 우측 스크롤 버튼(↑/↑/↓)이 작아 핀치 정확도 부족 시 오작동
  • Complete 컬럼이 체크박스 하나뿐 — 작업 진행률(예: 60%) 같은 중간 상태 표현 부재
  • Inactive item이 단순 dim — 왜 진행 불가인지(전제 작업 미완 등) 컨텍스트 부재

경쟁사 비교 · Caterpillar 320 vs DEVELON E23 · Part B 쇼룸

쇼룸에서 Caterpillar 320과 DEVELON E23을 1:1로 맞대는 비교 화면입니다. 좌측 카테고리 트리에서 Engine·Dimensions 같은 항목을 고르면 VS 헤더 아래 Specification·Unit·Value 3열 표에 두 모델의 같은 항목이 한 행에 정렬됩니다. 경쟁 모델은 회색, DEVELON은 오렌지 외곽으로 나눠 어느 쪽이 자사 장비인지 바로 알게 했고, 같은 행의 값을 좌우로 곧장 비교하게 했습니다.

  • Left — Category TreeEngine · Dimensions · Undercarriage · Hydraulic · Swing · Arm. 활성 항목은 오렌지 외곽 강조.
  • VS Header (Center)Caterpillar 320 / DEVELON E23 두 모델 헤더. 회색 vs 오렌지로 시각적 양분 — 어느 쪽이 우리 장비인지 즉시 식별.
  • Spec / Unit / Value ColumnsSpecification · Unit · Value 3열 구조. 모델별 동일 행에 같은 항목이 와 비교가 직선적.
  • DEVELON Side (Orange)우측 DEVELON 컬럼은 오렌지 외곽으로 강조 — 비교 대상이 아닌 "본인 장비"로 시각적 위계.
  • Same Row Alignment두 모델의 같은 항목이 한 행 안에 정렬 — Undercarriage width 3,065mm 같은 값이 두 컬럼에 동시 표시.
Worked well
  • VS 헤더의 회색 vs 오렌지 양분 — 첫 시선에서 어느 쪽이 우리 장비인지 즉시 인지, 브랜드 자체가 인터페이스
  • 좌측 카테고리 트리를 sticky로 유지 — 우측 데이터 스크롤 중에도 컨텍스트 잃지 않음
  • 같은 항목을 두 컬럼 동일 행에 정렬 — 별도 화면 전환 없이 직선적 비교 가능
Could be better
  • 두 컬럼 값이 동일할 때(예: Undercarriage width 3,065mm 양쪽 동일) 차이 없음을 시각화하는 표시 부재 — "=" 같은 동등 표시 필요
  • 스펙 수치 단위가 mm/cm³/hp 등 혼재 — 어느 수치가 큰 게 좋은지 컨텍스트 부재 (Higher is better 표시)
  • 같은 행에 6개 이상 반복 표시되는 항목이 있음 — 데이터 본드 검증 부족, UI보다 데이터 모델 정리가 선행됐어야

01

VR UI는 화면이 아니라 손의 거리다.

2D 화면은 사각형 안의 위계만 고민하면 되지만, VR은 사용자가 손을 뻗을 수 있는 거리 안에 핵심 액션을 배치해야 합니다. Handlebar를 손 가까이 묶은 결정이 그 답이었습니다.

02

색상은 컨텍스트를 갈아입는 가장 빠른 방법이다.

두 서브 콘텐츠를 한 시스템 안에서 운영할 때, 컴포넌트를 새로 만드는 대신 색상만 바꿔도 사용자는 다른 공간에 있다고 느낍니다. 사이언↔오렌지의 단순한 토글이 두 콘텐츠를 분리했습니다.

03

안전 경고는 디자인 시스템 위에 군림한다.

일관성이 디자인의 미덕이지만, 위험 상황에서는 일관성을 깨고 사용자의 시선을 강제로 끌어야 합니다. 사이언 프레임을 빨강으로 바꾸는 결정은 시스템 위반이 아니라 시스템의 정상 동작이었습니다.

/01—Overview

실제 중장비 없이 여러 작업 환경에서 굴착기 운전을 교육하는 시뮬레이터입니다. 입문자가 장비와 공사현장을 고르고 버킷·브레이커 같은 어태치먼트를 바꿔 끼우며 운전하기까지를 하나의 흐름으로 묶고, 콘텐츠 선택에서 자유모드와 시험모드로 나뉘게 했습니다. 중장비 현장 교육에 부지·건물·교육용 장비가 필요하다는 제약에서 출발해, 대형 화면 가독성과 DEVELON 브랜드 톤, 조이스틱·하드웨어 안내를 기준으로 초안부터 최종까지 UI를 단독 디자인했습니다.

사용자는 로비 → 중장비 선택 → 어태치먼트 장착 → 공사현장 선택 → 운전석 진입 순으로 단계를 밟습니다. 각 단계는 다음 단계의 전제가 되기 때문에, 화면마다 "지금 무엇을 고르는 중인지"를 상단에 고정해 맥락을 잃지 않도록 했습니다.

운전석에 진입하면 학습 모드가 둘로 갈립니다. 자유모드는 제약 없이 운전·어태치먼트 조작을 익히는 환경이고, 시험모드는 작업 단계 가이드를 따라가며 평가를 받는 구조입니다. 같은 운전석 화면이지만, 모드에 따라 화면에 떠 있는 정보의 밀도가 완전히 달라집니다.

Primary Interface

자유모드 운전자뷰

자유모드는 평가 없이 운전 자체를 익히는 모드라 화면 정보를 최소화했습니다. 상단을 비워 운전석 시야를 확보하고, 하단 컨텍스트 바에는 현재 모드와 장비 상태만 안내문 없이 표시했습니다. 주행·선회 조작은 좌측, 버킷·붐 같은 어태치먼트 제어는 우측에 대응시켜 전용 머신의 물리 레버와 화면 위치를 맞췄고, 좌우 손의 역할을 화면 좌우로 나눠 실제 장비를 다루는 감각에 가깝게 했습니다.

  • 최소 HUD자유모드는 평가가 없으므로 화면 정보를 최소화. 운전 자체에 몰입할 수 있도록 상단을 비웠습니다.
  • 조작계 영역 (좌)주행·선회 조작이 매핑되는 좌측 영역. 전용 머신의 물리 레버와 화면 위치를 일치시켜 학습 전이를 높임.
  • 어태치먼트 조작 (우)버킷·붐 등 어태치먼트 제어. 좌/우 손 역할을 화면 좌우로 분리해 실제 장비 조작 감각을 재현.
  • 하단 컨텍스트 바현재 모드·장비 표시. 자유모드에서는 안내문 없이 상태만 — 사용자가 자유롭게 탐색하도록.
Worked well
  • 좌/우 손 조작을 화면 좌우로 분리 — 전용 머신의 물리 레버 배치와 1:1 대응시켜 학습 전이를 높임
  • 평가가 없는 모드인 만큼 HUD를 과감히 비워 운전 몰입감 우선
  • 같은 운전석 뷰를 시험모드와 공유 — 모드 전환 시 환경이 바뀌지 않아 인지 부담 최소화
Could be better
  • 자유모드에 진입 가이드가 거의 없어, 입문자가 무엇부터 조작할지 막막할 수 있음
  • 현재 어떤 어태치먼트가 장착됐는지 운전 중 재확인할 방법이 약함

Primary Interface

시험모드 작업 단계 가이드

시험모드는 같은 운전자뷰를 쓰되 작업을 단계로 쪼개 안내하는 모드입니다. 현재 단계를 상단에 고정하고, 작업 가이드 카드에 지금 해야 할 작업을 텍스트와 아이콘으로 적었으며, 운전 화면 위에는 장비를 옮겨야 할 목표 지점을 하이라이트했습니다. 단계를 마칠 때마다 평가가 누적되고 감점·실격 조건 안내와 시험 채점으로 이어지게 해, 자유모드와 달리 무엇을 기준으로 평가받는지 분명히 보이게 했습니다.

  • 단계 표시시험모드는 작업이 단계로 쪼개짐. 현재 몇 단계인지를 상단에 고정해 진행 위치를 항상 인지.
  • 작업 가이드 카드"지금 해야 할 작업"을 텍스트·아이콘으로 명시. 자유모드와 가장 크게 다른 지점.
  • 목표 지점 하이라이트실제 운전 화면 위에 작업 목표를 시각적으로 강조 — 어디로 장비를 움직여야 하는지 직접 안내.
  • 진행 / 완료 액션단계 완료 시 다음으로. 가이드를 따라가며 평가가 누적되는 구조.
Worked well
  • 자유모드와 동일한 운전석 뷰 위에 가이드 레이어만 얹어, 두 모드가 별개 화면처럼 느껴지지 않음
  • 작업을 단계로 분절하고 목표 지점을 화면에 직접 표시 — 입문자도 "어디로 움직일지" 헤매지 않음
  • 단계 표시를 상단에 고정해 전체 진행 위치를 항시 인지
Could be better
  • 가이드 카드와 운전 화면이 시야를 분점 — 카드를 읽는 동안 운전 조작이 끊길 수 있음
  • 평가 기준(무엇이 통과/실패인지)이 화면상으로 충분히 드러나지 않음

Self-critique

돌아보기

잘 풀어낸 것

  1. 단계 진입 흐름로비부터 운전석까지를 선형 단계로 묶고 각 화면에 현재 선택 맥락을 고정 — 입문자가 길을 잃지 않음.
  2. 한 뷰, 두 모드자유모드와 시험모드가 같은 운전석 뷰를 공유하고 정보 레이어만 다르게 — 모드 전환의 인지 비용을 최소화.
  3. 물리 조작과의 매핑좌/우 손 조작을 화면 좌우로 분리해 전용 머신의 레버 배치와 일치 — 화면 학습이 실제 조작으로 전이.

다시 한다면

  1. 자유모드 온보딩제약이 없는 만큼 첫 진입자가 막막할 수 있음. 선택적으로 호출 가능한 가벼운 힌트 레이어가 있으면 좋았을 것.
  2. 평가 피드백시험모드의 통과/실패 기준이 화면상 약함. 단계별 결과를 더 명확히 시각화할 여지.
  3. 가이드와 조작의 시야 경합가이드 카드를 읽는 동안 운전 조작이 끊길 수 있음. 카드 위치·타이밍의 추가 검토 필요.

Reflection

01

비표준 해상도가 곧 제약이자 기회

4096×4320이라는 세로로 긴 환경은 일반 16:9 레이아웃 감각을 버리게 만들었다. 화면을 손 역할로 좌우 분할하는 결정은 이 제약에서 나왔다.

02

모드는 화면이 아니라 정보 밀도

자유모드와 시험모드를 별개 화면으로 만들지 않고, 같은 뷰 위 레이어의 차이로 정의한 것이 이 프로젝트의 핵심 판단이었다.

03

학습 전이를 디자인한다

화면 안 조작 위치를 실제 머신 레버와 맞추는 일은 UI를 넘어 "몸이 기억하는 학습"을 설계하는 작업이었다.

/01—Overview

강의가 아니라 직접 상황을 체험하며 마약의 위험을 알게 해 달라는 요청으로 만든 청소년 대상 VR 예방 교육 콘텐츠입니다. 튜토리얼을 거쳐 약물 선택과 체험, OX 퀴즈로 이어지는 짧은 학습 사이클로 구성하고, NHN Wonderverse 교육 프로그램 디자인을 바탕으로 친근한 톤과 큰 버튼을 적용했습니다. VR 멀미에 체험 연출까지 더해지면 몸에 부담이 크다는 점을 이전 VR 프로젝트 경험으로 알고 있어 30분/5분 경과 알림과 안전 구역 경고를 직접 제안해 넣었고, UI는 단독으로 디자인했습니다.

콘텐츠의 핵심은 약물 선택 → 학습 → OX 퀴즈로 도는 사이클입니다. 학습자가 직접 대상을 골라 정보를 보고, 그 자리에서 바로 OX로 확인하는 짧은 루프가 반복됩니다. 한 번에 모든 걸 가르치기보다, 작은 단위로 끊어 스스로 점검하게 하는 방식입니다.

주제가 민감한 만큼 진입부의 톤 관리가 중요했습니다. 타이틀과 콘텐츠 안내·주의사항 단계에서 분위기를 정돈하고, VR이 처음인 사용자를 위해 조작법은 언제든 Popup으로 호출할 수 있게 했습니다. 학습 흐름을 끊지 않으면서 도움을 받을 수 있는 구조입니다.

Primary Interface

약물 선택

약물 선택은 학습자가 무엇을 체험할지 직접 고르는 진입점입니다. 주제를 정해 주기보다 스스로 고르게 해 무거운 주제를 사용자 주도 학습으로 시작하게 했고, 학습 대상을 카드로 나눠 VR에서 핀치로 집기 쉬운 크기와 간격으로 배치했습니다. 선택과 확정 동선을 나눠 잘못 눌러 바로 체험에 들어가는 일을 막았고, 선택 뒤에는 경고 팝업과 시간 경과 연출, 재경고가 차례로 이어지게 했습니다.

  • 선택 안내 헤더"무엇을 학습할지" 직접 고르게 하는 진입점. 강요가 아니라 사용자 주도 학습으로 톤을 잡음.
  • 선택 카드학습 대상을 카드로 분리. VR 시야에서 핀치로 집기 쉬운 크기·간격으로 배치.
  • 시각적 위계선택 가능한 항목을 또렷한 대비로 — 어두운 배경 위에서 무엇을 고를 수 있는지 즉시 식별.
  • 진행 / 진입 액션선택 후 학습으로. 선택과 확정 동선을 분리해 잘못 누름을 방지.
Worked well
  • "고르게 하는" 진입으로 예방 교육 특유의 강요 톤을 피함 — 사용자 주도 학습으로 프레이밍
  • 선택 항목을 카드로 분리해 VR 핀치 조작에 최적화 — 크기·간격이 헤드셋 시야 기준
  • 어두운 배경 위 대비로 선택 가능 영역을 명확히 — 입문자도 무엇을 할지 즉시 인지
Could be better
  • 이미 학습한 항목과 미학습 항목의 구분 표시가 약함 — 진행 상태를 카드에 누적하면 좋았을 것
  • 선택지가 많아질 경우의 스크롤·페이지 전략이 화면상 드러나지 않음

Primary Interface

OX 퀴즈

OX 퀴즈는 체험한 내용을 바로 확인하는 마지막 단계입니다. 긴 지문 대신 즉시 판단할 수 있는 짧은 명제 하나를 던지고, 큰 O와 X 버튼을 좌우로 크게 떼어 두어 VR에서도 망설이지 않고 정확하게 고르게 했습니다. 선택 직후 정답·오답과 해설을 바로 보여 주어 학습과 확인 사이의 시간차를 없앴고, 마지막 문항은 최종 해설로 마무리했습니다.

  • 질문 텍스트학습 직후 핵심을 한 문장으로 되묻음. 긴 지문 대신 즉시 판단 가능한 짧은 명제.
  • O 버튼좌측 대형 O. 두 선택지만 두어 VR 시야에서 망설임 없이 고를 수 있게 함.
  • X 버튼우측 대형 X. O/X를 좌우로 크게 분리해 오선택 방지 + 핀치 정확도 확보.
  • 정답 피드백선택 직후 맞고 틀림을 즉시 표시 — 학습과 확인 사이 시간차를 없애 기억에 고정.
Worked well
  • 선택지를 O/X 둘로만 단순화 — VR 시야에서 망설임·오조작을 최소화
  • O/X를 좌우 대형으로 분리해 핀치 정확도 확보, 시각적으로도 직관적
  • 학습 직후 즉시 확인하는 배치로 정보와 점검 사이 간격을 없앰
Could be better
  • 오답 시 "왜 틀렸는지" 해설 깊이가 화면상 드러나지 않음 — 예방 교육에서는 이 부분이 핵심
  • 여러 문항의 누적 결과·복습 동선이 단일 퀴즈 화면만으로는 약함

Self-critique

돌아보기

잘 풀어낸 것

  1. 강요하지 않는 진입사용자가 직접 학습 대상을 고르게 해, 예방 교육 특유의 위협 톤을 피하고 자기주도 학습으로 프레이밍.
  2. 짧은 학습 사이클선택 → 학습 → OX로 도는 작은 루프. 한 번에 가르치지 않고 끊어 확인하게 해 부담과 망각을 줄임.
  3. VR 조작 최적화선택은 카드, 퀴즈는 좌우 대형 O/X로 — 헤드셋 시야와 핀치 정확도를 기준으로 인터랙션을 단순화.

다시 한다면

  1. 오답 해설 깊이예방 교육의 핵심은 "왜 틀렸나"의 설명. OX 정오 표시를 넘어선 해설 레이어가 더 필요했음.
  2. 진행 상태 누적학습/미학습 항목 구분과 전체 진행률 표시가 약함. 반복 사이클인 만큼 진척 가시화가 동기에 중요.
  3. 복습 동선틀린 문항으로 다시 돌아가는 경로가 단일 퀴즈 화면만으로는 부족.

Reflection

01

무거운 주제일수록 톤이 설계다

마약 예방은 자칫 공포 마케팅이 되기 쉽다. 색·동선·문장의 톤을 차분하게 잡는 것 자체가 이 콘텐츠의 핵심 디자인 결정이었다.

02

짧게 끊어야 남는다

한 번에 많은 정보를 주기보다, 선택·학습·확인을 작은 루프로 끊었다. 청소년 학습자에게는 분량보다 리듬이 중요했다.

03

VR은 단순함이 정확함

헤드셋 시야에서는 선택지가 적고 클수록 정확하다. O/X 둘로 줄인 결정은 제약이 아니라 매체에 맞춘 답이었다.

/01—Overview

KTX 정비기지를 3D 메타버스로 옮기고 그 위에 모니터링·분석·일정 관리를 얹은 코레일 플랫폼입니다. 포항사업소 열차 입·출고와 선로 점유를 한눈에 관리하려는 요청으로 시작해, 다음 해 MSDS 안전맵·차륜마모도 AI·공정스케줄링·ECO를 한 곳에서 쓰고 싶다는 요청이 더해지면서 관리는 웹, 관제는 앱, 모니터링은 태블릿으로 나눈 멀티 디바이스 구조로 확장했습니다. 서브시스템 통합 허브와 코레일 브랜드 톤, 대시보드·리스트 체계를 기준으로 2024 1차부터 2025 고도화까지 UI를 단독 디자인했습니다.

다섯 개의 서브시스템 — 메타버스 PC Hub, Mobile, ECO Web, 차륜마모도 AI, 공정스케줄링 — 은 각자 역할과 사용 맥락이 다릅니다. PC 메타버스는 3D 공간에서 안전맵·경정비 모니터링·MSDS를 통합하고, Mobile은 현장 작업자가 즉시 조회하는 경량 인터페이스로 분리했습니다.

ECO 대시보드, 차륜 마모 예측 AI, 공정스케줄링은 Web 기반의 분석·관리 도구입니다. 디바이스(PC 3D / Mobile / Web)와 목적(체험 / 조회 / 분석)이 모두 다른 시스템들을, 같은 시각 언어 위에서 일관되게 묶는 것이 디자인의 중심이었습니다.

Primary Interface

메타버스 MSDS 안전맵

메타버스 MSDS 안전맵은 정비고 공간 안에서 안전 정보를 찾는 화면입니다. 경정비동·중정비동 같은 구역을 3D 공간으로 옮기고 MSDS와 위험 구역을 실제 배치에 맞춘 노드로 올려, 현장 동선대로 이동하며 확인하게 했습니다. 상단에는 지금 보고 있는 구역을 항상 표시해 위치를 잃지 않게 했고, 사이드 컨트롤의 필터와 레이어 토글로 안전·MSDS·설비 정보를 켜고 끄며 화면 밀도를 조절하게 했습니다.

  • 공간 컨텍스트 헤더현재 보고 있는 정비고 구역을 상단에 명시. 3D 공간에서 길을 잃지 않도록 위치를 항시 표시.
  • 안전 정보 노드MSDS·위험 구역을 맵 위 노드로. 실제 정비고 배치와 1:1 대응시켜 직관적 탐색.
  • 3D 공간 뷰디지털 트윈의 핵심 — 정비고를 그대로 옮긴 3D 공간. 작업자가 실제 동선으로 이동하며 정보 확인.
  • 사이드 컨트롤맵 필터·레이어 토글. 안전·MSDS·설비 등 정보 레이어를 켜고 끄며 화면 밀도를 조절.
Worked well
  • 안전 정보를 맵 노드로 — 실제 정비고 배치와 대응시켜 텍스트 목록보다 직관적
  • 3D 공간 동선을 그대로 따라가며 정보를 확인하는 디지털 트윈 본연의 강점 활용
  • 정보 레이어 토글로 화면 밀도를 사용자가 조절 — 복잡한 공간을 단계적으로 탐색
Could be better
  • 3D 공간 이동의 학습 곡선 — 처음 진입한 작업자를 위한 길찾기 보조가 더 필요
  • 노드가 많아질 때의 겹침·우선순위 처리 전략이 화면상 약함

Primary Interface

차륜 마모 예측 AI

AI가 산출한 차륜 마모 추이로 정비 시점을 판단하는 분석 화면입니다. 좌측에서 차량과 차륜 단위로 분석 대상을 고르면 우측에 결과가 나오는 흐름으로 만들고, 현재값과 예측값을 한 시계열 그래프에서 비교하게 했습니다. 그래프로는 추세를, 함께 둔 데이터 테이블로는 정확한 수치를 읽게 했으며, 교체 임계치에 도달한 항목은 강조해 분석 결과가 곧바로 정비 지시로 이어지게 했습니다.

  • 예측 대상 선택차량·차륜 단위로 분석 대상을 지정. 좌측에 선택, 우측에 결과 — 분석 도구의 표준 좌→우 흐름.
  • 마모 예측 그래프AI가 산출한 마모 추이를 시계열로. 현재값과 예측값을 한 그래프에서 비교해 정비 시점 판단.
  • 데이터 테이블예측 수치를 표로 병기. 그래프로 추세를, 표로 정확한 값을 — 두 표현을 함께 제공.
  • 임계 알림교체 임계치 도달 항목을 강조. 분석 결과가 곧바로 행동(정비 지시)으로 이어지도록.
Worked well
  • 그래프(추세) + 테이블(정확값)을 함께 제공해 판단과 검증을 한 화면에서
  • 좌 선택 → 우 결과의 표준 분석 흐름으로 데이터 도구 학습 비용 최소화
  • 예측 결과를 임계 알림으로 연결 — 분석이 정비 행동으로 직결되는 구조
Could be better
  • AI 예측의 신뢰도·근거 표시가 약함 — 작업자가 결과를 얼마나 믿을지 판단할 단서 부족
  • 메타버스·Mobile과의 데이터 연계 동선이 이 화면만으로는 드러나지 않음

Self-critique

돌아보기

잘 풀어낸 것

  1. 다섯 시스템의 시각 통일디바이스·목적이 다른 다섯 서브시스템을 시그니처 블루 하나로 묶어 "같은 플랫폼"으로 인식시킴.
  2. 맥락별 디바이스 분리체험은 PC 3D, 조회는 Mobile, 분석은 Web — 사용 맥락에 맞춰 인터페이스를 나눠 각자 최적화.
  3. 분석을 행동으로 연결차륜 AI 예측을 임계 알림으로 이어, 데이터가 정비 지시로 직결되도록 설계.

다시 한다면

  1. 시스템 간 연계 동선메타버스·Web·Mobile이 같은 데이터를 보지만, 한 시스템에서 다른 시스템으로 넘어가는 동선이 약함.
  2. 3D 공간 길찾기디지털 트윈의 강점인 3D 공간이 입문자에겐 학습 부담. 진입 보조·미니맵 등이 더 필요했음.
  3. AI 신뢰도 표시예측 결과의 근거·신뢰도를 함께 보여줘야 작업자가 판단에 활용할 수 있음.

/01—Overview

PC·모바일·VR·HoloLens 어느 기기로든 같은 가상 공간에서 회의하고 싶다는 요청으로 만든 KISTI의 개방형 XR 협업 플랫폼 XU:M입니다. 사람이 모여 협업하는 공간과 그 공간을 운영하는 관리 도구를 하나의 포털에 담았고, 보라(#6235FF) 브랜드 톤과 아이콘 세트, 아바타·공간 입장 흐름을 중심으로 설계했습니다. 2023 Web 이후 2024에 전체 톤을 바꾸고 PC 앱과 VR/AR을 추가하며 메뉴 구조를 개편했고, UI를 단독으로 디자인했습니다.

사용자는 로그인 후 공간 진입 · 회의 목록으로 협업에 들어가고, My Info(아바타) · 콘텐츠 관리로 개인 영역을 정리합니다. 이 영역은 "들어가서 함께하는" 경험이라, 진입 동선과 시각적 몰입을 우선했습니다.

관리자는 세션 관리 · 로그 관리로 플랫폼 전체를 운영합니다. 이쪽은 "한눈에 파악하고 통제하는" 도구라, 정보 밀도와 테이블 가독성을 우선했습니다. 같은 디자인 시스템 위에서 두 영역의 정보 위계를 분리해, 역할에 따라 화면의 성격이 달라지도록 설계했습니다.

같은 공간, 네 가지 기기

XU:M은 PC · 모바일 · VR · HoloLens 어느 기기로 들어와도 같은 가상 공간에서 만나도록 만든 플랫폼입니다. 공간과 콘텐츠는 하나로 두고, 기기마다 달라지는 입력 방식만 따로 풀었습니다. PC는 키보드 · 마우스 조작키 도움말을 공간 위 팝업으로 띄우고, 모바일은 세로 웹뷰에서 파일을 고르고 올리게 했습니다. VR은 Meta Quest 컨트롤러 버튼마다 기능을 붙여 안내하고, HoloLens 2는 손목을 보는 핸드 트래킹 제스처로 메뉴를 부르게 했습니다.

Primary Interface

공간 진입 (사용자)

공간 진입은 사용자가 협업 공간에 들어가기 직전의 화면입니다. 상단에 진입할 공간의 이름과 상태를 두고, 공간 프리뷰로 내부를 미리 보여 주어 XR 공간에 들어갈 때의 막연함을 줄였습니다. 현재 인원과 세션 상태 같은 참여 정보를 함께 보여 빈 공간인지 회의가 진행 중인지 미리 판단하게 했고, 미리보기에서 정보 확인으로 이어지는 동선 끝에 입장 버튼을 두었습니다.

  • 공간 헤더진입할 공간의 이름·상태를 상단에. 어떤 협업 공간으로 들어가는지 진입 전 명확히 인지.
  • 공간 프리뷰들어가기 전 공간을 미리 보여줌 — XR 진입의 불확실성을 줄이고 기대를 형성.
  • 참여 정보현재 인원·세션 상태 등 협업 컨텍스트. 빈 공간인지 진행 중인지 진입 전 판단.

Worked well
  • 진입 전 공간 프리뷰로 XR 특유의 "들어가 보기 전엔 모름" 불확실성을 완화
  • 참여 인원·세션 상태를 진입 전 노출해 빈 방 입장 같은 헛걸음 방지
  • 미리보기 → 정보 → 진입의 직선 동선으로 협업 진입 마찰 최소화
Could be better

관리자가 세션을 통제하는 화면입니다. 몰입을 우선한 사용자 화면과 달리 상단에는 세션 검색과 기간·상태 필터를 모은 관리 헤더를 두어 기능 밀도를 높였습니다. 세션 목록은 여러 세션을 한눈에 비교하도록 테이블로 구성하고 상태 컬럼은 색과 라벨로 활성·대기·종료를 구분했으며, 종료·상세 같은 운영 액션은 행 우측에 정렬해 행 단위로 바로 처리하게 했습니다.

  • 관리 액션세션 종료·상세 등 운영 액션. 행 단위로 즉시 통제할 수 있게 우측 정렬.
Worked well

  • 상태를 색·라벨로 구분해 다수 세션을 스캔하듯 빠르게 파악

잘 풀어낸 것

  1. 두 성격의 공존몰입형 사용자 영역과 밀도형 관리자 영역을, 같은 시스템 위에서 정보 위계만 달리해 모순 없이 통합.

다시 한다면

  1. 다중 디바이스 명시"다중 디바이스 지원"이 강점이지만, 디바이스별 진입·경험 차이가 화면에서 충분히 드러나지 않음.

/01—Overview

스마트팩토리·그린에너지·반도체, 성격이 다른 세 산업 교육을 하나의 XR 플랫폼에 담은 프로젝트입니다. 도메인마다 가르치는 방식은 다르지만 진입 경험까지 제각각이면 학습자가 매번 새 프로그램을 익혀야 하기 때문에, 로비·훈련선택·훈련 메뉴로 이어지는 진입은 공통으로 두고 그 뒤를 도메인별로 나눴습니다. 스마트팩토리는 OMS·WMS 업무 화면 실습으로, 그린에너지와 반도체는 이론학습에서 O·X·사지선다 평가와 실습으로 이어집니다.

사용자는 하나의 메타버스 Lobby에서 그린에너지 · 반도체 · 스마트팩토리 중 하나로 분기합니다. 로비·아바타·이동 같은 뼈대는 세 도메인이 공유하기 때문에, 한 번 익힌 진입 방식이 다른 도메인에서도 그대로 통합니다.

분기 이후의 학습 방식은 도메인마다 다릅니다. 그린에너지는 설비를 직접 돌려보는 3D 회전 + 이론학습, 반도체는 패키징 단계를 짚는 3D 상호작용 + 이론학습, 스마트팩토리는 게임처럼 라인에 진입해 오더를 처리하는 OMS 시뮬레이션입니다. 같은 골격 위에서 도메인의 성격에 맞게 인터랙션 밀도를 다르게 가져갔습니다.

Primary Interface

그린에너지 3D 회전 학습

그린에너지 이론학습은 설비를 직접 돌려 보며 구조를 익히는 화면입니다. 화면 중앙을 3D 설비 뷰포트에 내주어 드래그로 회전하게 하고, 좌측에는 이론 패널을 고정해 돌려 보는 즉시 무엇을 보고 있는지 읽게 했습니다. 3D 조작이 처음인 학습자를 위해 회전·확대·리셋 버튼을 우측에 모아 같은 동작을 버튼으로도 하게 했고, 하단 진행 바로 현재 학습 위치를 늘 보여 주었습니다.

  • 3D 설비 뷰포트화면 중앙을 설비 자체에 내줌. 학습자가 드래그로 직접 돌려보며 구조를 파악하는, 이 도메인의 핵심 인터랙션.
  • 이론 패널 (좌)3D 조작과 이론 설명을 한 화면에 병치. 돌려보는 즉시 옆에서 무엇을 보는지 읽을 수 있게 좌측에 고정.
  • 회전 / 시점 컨트롤 (우)회전·확대·리셋을 우측에 모음. 3D 조작이 처음인 학습자도 버튼으로 같은 동작을 수행하도록 이중 경로 제공.

Primary Interface

스마트팩토리 오더관리(OMS)

스마트팩토리 오더관리(OMS)는 3D 조작 대신 데이터로 라인을 운영하는 실무 화면입니다. 상단에 처리 중·대기·완료 오더를 요약해 무엇을 운영 중인지 먼저 파악하게 하고, 좌측 오더 리스트에서 주문을 고르면 우측에 어느 라인과 공정에 걸리는지 매핑되게 해 데이터 결정이 현장 상태로 바로 이어지게 했습니다. 실행·배정 같은 확정 액션은 하단에 모아 결정과 실행의 경계를 분명히 했습니다.

  • 오더 현황 헤더처리 중·대기·완료를 상단에 요약. 게임처럼 라인에 들어와 있지만, 무엇을 운영 중인지는 데이터로 먼저 인지하게 함.
  • 오더 리스트 (좌)처리할 주문을 목록으로. 3D 도메인과 달리, 여기서는 "선택 → 배정"이라는 실무 운영 동선이 학습의 중심.
  • 라인 / 공정 상태 (우)선택한 오더가 어느 라인에 걸리는지 우측에 매핑. 데이터 결정이 곧바로 현장 상태로 반영되는 구조.
  • 실행 / 배정 액션하단에 확정 액션을 모아 오조작 방지. 운영 시뮬레이션인 만큼 "결정 → 실행"의 경계를 분명히 함.
Worked well
  • 인게임 진입과 데이터 관리(OMS)를 한 흐름으로 묶어, "라인에 들어와 직접 운영한다"는 실무 감각을 재현
  • 좌 오더 선택 → 우 라인 반영의 표준 운영 동선으로 데이터 도구 학습 비용을 낮춤
  • 결정과 실행을 분리(하단 액션)해 운영 시뮬레이션의 오조작을 방지
Could be better
  • 오더가 많아질 때의 정렬·필터·페이지 전략이 화면상 드러나지 않음
  • 잘못된 배정의 결과(지연·실패)가 어떻게 피드백되는지 약함 — 운영 학습의 핵심 지점

Self-critique

돌아보기

잘 풀어낸 것

  1. 공통 진입 + 도메인 분기로비·이동 같은 뼈대를 하나로 공유해, 도메인을 옮겨도 진입 방식을 다시 배우지 않게 만든 구조적 결정.
  2. 도메인 색 분리플랫폼 블루 위에 그린·시안·앰버를 얹어, 지금 어느 산업 안에 있는지를 색만으로 즉시 인지하게 함.
  3. 성격에 맞춘 인터랙션 밀도3D 회전(그린)부터 데이터 운영(팩토리)까지, 같은 골격 위에서 도메인마다 인터랙션 밀도를 다르게 가져감.

다시 한다면

  1. 학습 완료 기준3D를 어느 정도 봐야, OMS를 몇 건 처리해야 "완료"인지 기준이 도메인별로 일관되지 않음.
  2. 도메인 간 진척 통합세 도메인의 진행률을 로비에서 한눈에 보는 통합 대시보드가 있었으면 학습 동기에 더 좋았을 것.
  3. 색의 접근성도메인을 색에 크게 의존 — 색각 이상 사용자를 위한 보조 라벨·아이콘 병기가 더 필요.

Reflection

01

다른 산업을 한 플랫폼에 담는 법

성격이 다른 세 교육을 억지로 똑같이 만들 수도, 완전히 따로 만들 수도 있었다. 진입은 공유하고 학습은 분기한 절충이 이 프로젝트의 핵심 판단이었다.

색은 가장 빠른 길잡이

도메인마다 색을 분리하니, 화면에 라벨이 없어도 "지금 어디에 있는지"가 즉시 읽혔다. 멀티 도메인에서 색은 장식이 아니라 내비게이션이었다.

인터랙션 밀도도 콘텐츠다

같은 UI 골격 위에서 3D 조작과 데이터 운영은 전혀 다른 밀도를 요구했다. 도메인의 성격에 인터랙션을 맞추는 일 자체가 설계였다.

/01—Overview

비싼 시험 장비 없이도 인장·경도·열처리 실습을 할 수 있게 해 달라는 요청으로 만든 한국기술교육대학교 재료시험·열처리 시뮬레이터입니다. 인장시험·경도시험·퀜칭 템퍼링·어닐링 노멀라이징 실습을 한 시뮬레이터에 담으면서, 학습자가 매번 새 UI를 배우지 않도록 통일된 UI 템플릿 위에 실험 절차 단계 안내와 기기별 레이아웃, 데이터 입력·보고서를 얹었습니다. PC로 시작해 zSpace·Mobile로 확장했고, 초안(Concept)부터 최종 디자인까지 UI를 단독으로 디자인했습니다.

네 종 모두 좌상단 KOREATECH 로고 · 상단 단계 탭 · 우측 컨트롤(가이드북·조견표) · 하단 자막·페이지 카운터라는 동일한 골격을 공유합니다. 한 시험에서 익힌 화면 구조가 다른 시험에서도 그대로 통하기 때문에, 학습자는 절차에만 집중할 수 있습니다.

분기되는 것은 두 가지입니다. 하나는 컬러 시스템 — 인장(그린) · 경도(시안) · 어닐링/노멀라이징(블루) · 퀜칭/템퍼링(오렌지)으로 시험을 색으로 즉시 구분합니다. 다른 하나는 전용 실험 화면 — 만능재료시험기, 비커스 경도계 프로그램, 전기로·온도 컨트롤러, 퀜칭 수조처럼 각 시험의 실제 장비를 그대로 재현했습니다.

경도시험 압입자 확대기 (HB 산출)

압흔을 측정해 브리넬 경도(HB)를 구하는 압입자 확대기 화면입니다. 측정 화면 위에 '시험하중 ÷ 압입자 자국의 표면적' 공식을 함께 띄워 무엇을 왜 재는지 연결하고, 압흔을 단면 다이어그램으로 보여 주며 압입자국 지름(d)·깊이(h)·압입자 지름(D)을 그림에 직접 표기해 변수를 헷갈리지 않게 했습니다. 하단 자막으로는 자국 면적을 기준으로 하중을 나눠 경도값을 계산하는 다음 행동을 안내했습니다.

  • HB 산출 공식"시험하중 ÷ 압입자 자국의 표면적". 측정 화면 위에 공식을 함께 띄워, 무엇을 왜 재는지 연결.
  • 압흔 단면 다이어그램시험편 표면에 생긴 압흔을 단면으로 시각화. 측정값이 어떤 기하에서 나오는지 직관적으로 보여줌.
  • d · h · D 치수 표기압입자국 지름(d)·깊이(h)·압입자 지름(D)을 다이어그램에 직접 라벨링해 변수 혼동을 줄임.
  • 측정 가이드 자막"자국의 면적을 기준으로 하중을 나누어 경도값(HB)을 계산"을 하단에 명시해 다음 행동을 안내.
Worked well
  • 측정 화면 위에 공식과 단면 다이어그램을 겹쳐, "재는 행위"와 "계산 원리"를 한 화면에서 연결
  • d·h·D를 다이어그램에 직접 라벨링해 변수 혼동을 줄이고 개념을 시각으로 고정
  • 하단 자막으로 다음 행동을 명시해, 측정 절차가 끊기지 않게 안내
Could be better
  • 브리넬·로크웰·비커스가 한 시험 안에 섞여, 지금 어떤 경도법을 측정 중인지 화면상 구분이 약함
  • 측정 오차나 재측정 동선이 단일 화면만으로는 드러나지 않음

Self-critique

돌아보기

잘 풀어낸 것

  1. 공통 UI 베이스단계 탭·로고·컨트롤·자막을 네 시험이 공유 — 한 번 익힌 화면 구조가 다른 시험에도 그대로 통하게 설계.
  2. 시험별 컬러 분리그린·시안·블루·오렌지로 네 시험을 색으로 즉시 구분 — 라벨을 읽기 전에 어떤 시험인지 인지하게 함.
  3. 실장비 UI 재현만능시험기·경도계 프로그램·온도 컨트롤러를 실제에 가깝게 재현해, 화면 학습이 실장비 조작으로 전이되도록.

다시 한다면

  1. 단계 탭 명칭 통일시험마다 탭 명칭이 달라(시험준비/열처리/결과관찰 vs 시험조건설정/수행/분석) 공통 베이스의 일관성이 흔들림.
  2. 경도법 구분브리넬·로크웰·비커스가 한 시험에 섞여, 지금 어떤 경도법을 다루는지 화면상 구분이 약함.
  3. 입력값 검증시험 조건 입력의 유효 범위 안내가 약해, 잘못된 값도 그대로 저장될 수 있음.

Reflection

01

여러 실험을 한 베이스로

장비도 절차도 다른 네 시험을 묶는 답은 "공통 골격 + 색·전용 화면 분기"였다. 베이스를 공유한 덕에 학습자는 절차에만 집중할 수 있었다.

02

색이 곧 이름표

시험마다 색을 분리하니 라벨을 읽기 전에 어떤 시험인지 읽혔다. 멀티 시험 시뮬레이터에서 색은 장식이 아니라 길잡이였다.

03

실장비를 화면에 옮긴다

만능시험기·경도계 프로그램·온도 컨트롤러를 실제 UI에 가깝게 옮기는 일은, 화면을 넘어 "실습장에서의 손"을 설계하는 작업이었다.
