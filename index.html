Request

“작업 절차가 서식 · 무전 · 현장 조치로 흩어져 있어, 신입이 순서대로 익힐 수 있는 훈련이 필요해요.”

“실제 서식도 그대로 작성해 보고, 열차 접근 대응도 반복해서 연습할 수 있게 해 주세요.”

Direction

디자인 방향

  • 단계 카드 + 잠금 — 현장 점검 · 입문 · 실습 · 평가를 카드로 나누고 순서를 잠금으로 지키게 했습니다.
  • 서식 하이라이트 안내 — 실제 서식을 팝업으로 띄우고 지금 채울 칸을 하이라이트와 자막으로 안내했습니다.
  • Unity 리소스 체계 — 9-slice와 네이밍 규칙(ui_btn_ · ui_bg_ · ui_img_)으로 개발 전달용 리소스를 정리했습니다.

/01—Overview

실선(實船) 한 척의 작동 메커니즘을 PC 화면 안으로 옮겨오는 일. 운항팀·교육생·유지보수 인력이 모두 같은 환경에서 학습하고 진단할 수 있는 통합 콘텐츠를 만드는 것이 목표였습니다.

LNG 운반선은 수백 개의 탱크·밸브·펌프·배관이 얽힌 거대한 시스템입니다. 현장 인력이 이 구조를 익히려면 수개월의 도제식 학습이 필요했고, 안전 사고 대응 훈련도 실선에서는 사실상 불가능했습니다.

이 프로젝트는 그 격차를 메우는 작업이었습니다. 선체 외관부터 카고 핸들링 룸 내부의 밸브 한 개까지 모두 3D로 재현하고, 그 위에 실시간 데이터 스트림과 IGC·매뉴얼 문서를 얹었습니다.

풀어야 했던 문제는 명확했습니다. "무거운 정보를 가볍게 다루는 인터페이스" — 3D 뷰포트의 몰입감을 해치지 않으면서, 동시에 100개가 넘는 시그널과 컨트롤을 한 번에 접근할 수 있도록.

Primary Interface

고도화 메인 · 8196 Ship Model dashboard

두 개의 메인 작업 화면. 고도화 메인은 8196 선박 모델의 시스템별 진입점을 카드 그리드로 보여주는 허브이고, POC 메인은 한 시스템(LDC) 안에서 3D 모델·게이지·실시간 시그널을 한 화면에 펼치는 작업 화면입니다.

  • Top Bar — Persistent Context로고·홈·알림·시계가 어느 페이지에서도 같은 위치에 고정. 사용자의 위치 감각 유지.
  • Header + About + Pagination선택된 8196 SHIP MODEL 명시, About 모달 호출, 5개 선박 모델 간 페이지 이동.
  • System Cards (6-up Grid)CHS · CMS · ERS · GE · PMS 등 시스템별 카드. 3D 썸네일 + 모드 선택 + 진입 CTA.
  • Recent + Favorites최근 콘텐츠와 즐겨찾기를 좌우 평행 리스트로. 동일한 시각 패턴으로 두 리스트를 스캔.

중장비 정비 교육은 본래 실제 장비 + 정비사 + 안전관리자 + 작업 공간이 모두 필요합니다. 한 사람을 OJT로 키우기 위해 수개월의 라인이 묶이고, 사고 위험 때문에 신입은 단순 보조만 가능했습니다.

이 프로젝트는 그 비용 구조를 메타퀘스트로 옮기는 작업이었습니다. Part A는 정비 시뮬레이션 — 안전장구 착용부터 엔진 오일 교체, 필터 청소까지 손동작 기반으로 체험. Part B는 쇼룸 — 학습 종료 후 DEVELON 장비와 경쟁사(Caterpillar 등) 장비를 같은 공간에 배치해 치수·스펙을 직접 비교.

풀어야 했던 문제: VR 공간에서 떠다니는 UI — 데스크탑처럼 화면 모서리에 고정할 수 없고, 사용자가 머리를 돌릴 때마다 카드가 시야 밖으로 사라짐. 코너 컷 SVG 프레임 + 그리드 도트 백드롭으로 "실제 HUD 같은" 인상을 유지하되, 핵심 액션은 핸들바 같은 손 가까운 위치에 묶었습니다.

/01—Overview

실제 굴착기 운전석 뷰를 전용 시뮬레이션 머신 위에 재현하는 일. 입문자가 장비를 고르고, 어태치먼트를 끼우고, 현장에 들어가 직접 운전하기까지의 전 과정을 하나의 흐름으로 묶는 것이 목표였습니다.

사용자는 로비 → 중장비 선택 → 어태치먼트 장착 → 공사현장 선택 → 운전석 진입 순으로 단계를 밟습니다. 각 단계는 다음 단계의 전제가 되기 때문에, 화면마다 "지금 무엇을 고르는 중인지"를 상단에 고정해 맥락을 잃지 않도록 했습니다.

운전석에 진입하면 학습 모드가 둘로 갈립니다. 자유모드는 제약 없이 운전·어태치먼트 조작을 익히는 환경이고, 시험모드는 작업 단계 가이드를 따라가며 평가를 받는 구조입니다. 같은 운전석 화면이지만, 모드에 따라 화면에 떠 있는 정보의 밀도가 완전히 달라집니다.

Primary Interface

자유모드 운전자뷰

콘텐츠의 핵심은 운전석 진입 후의 두 모드. 자유모드와 시험모드가 같은 뷰를 어떻게 다르게 쓰는지가 이 프로젝트의 중심 결정이었습니다.

  • 최소 HUD자유모드는 평가가 없으므로 화면 정보를 최소화. 운전 자체에 몰입할 수 있도록 상단을 비웠습니다.
  • 조작계 영역 (좌)주행·선회 조작이 매핑되는 좌측 영역. 전용 머신의 물리 레버와 화면 위치를 일치시켜 학습 전이를 높임.
  • 어태치먼트 조작 (우)버킷·붐 등 어태치먼트 제어. 좌/우 손 역할을 화면 좌우로 분리해 실제 장비 조작 감각을 재현.
  • 하단 컨텍스트 바현재 모드·장비 표시. 자유모드에서는 안내문 없이 상태만 — 사용자가 자유롭게 탐색하도록.

  • 목표 지점 하이라이트실제 운전 화면 위에 작업 목표를 시각적으로 강조 — 어디로 장비를 움직여야 하는지 직접 안내.

/01—Overview

예방 교육이라는 무거운 주제를 청소년이 부담 없이 진입할 수 있는 짧은 학습 사이클로 옮기는 일. 정보 전달과 위협이 아니라, 스스로 판단해 보게 만드는 구조가 목표였습니다.

콘텐츠의 핵심은 약물 선택 → 학습 → OX 퀴즈로 도는 사이클입니다. 학습자가 직접 대상을 골라 정보를 보고, 그 자리에서 바로 OX로 확인하는 짧은 루프가 반복됩니다. 한 번에 모든 걸 가르치기보다, 작은 단위로 끊어 스스로 점검하게 하는 방식입니다.

주제가 민감한 만큼 진입부의 톤 관리가 중요했습니다. 타이틀과 콘텐츠 안내·주의사항 단계에서 분위기를 정돈하고, VR이 처음인 사용자를 위해 조작법은 언제든 Popup으로 호출할 수 있게 했습니다. 학습 흐름을 끊지 않으면서 도움을 받을 수 있는 구조입니다.

약물 선택

콘텐츠의 중심은 "고르고 → 확인하는" 사이클. 약물 선택과 OX 퀴즈가 이 루프의 양 끝입니다.

  • 선택 안내 헤더"무엇을 학습할지" 직접 고르게 하는 진입점. 강요가 아니라 사용자 주도 학습으로 톤을 잡음.
  • 선택 카드학습 대상을 카드로 분리. VR 시야에서 핀치로 집기 쉬운 크기·간격으로 배치.
  • 시각적 위계선택 가능한 항목을 또렷한 대비로 — 어두운 배경 위에서 무엇을 고를 수 있는지 즉시 식별.
  • 진행 / 진입 액션선택 후 학습으로. 선택과 확정 동선을 분리해 잘못 누름을 방지.

/01—Overview

사람이 모여 협업하는 XR 공간과, 그 공간을 운영하는 관리 도구. 성격이 정반대인 두 영역을 하나의 포털 안에서 모순 없이 공존시키는 것이 과제였습니다.

사용자는 로그인 후 공간 진입 · 회의 목록으로 협업에 들어가고, My Info(아바타) · 콘텐츠 관리로 개인 영역을 정리합니다. 이 영역은 "들어가서 함께하는" 경험이라, 진입 동선과 시각적 몰입을 우선했습니다.

/01—Overview

성격이 전혀 다른 세 산업 교육을 하나의 플랫폼에 담는 일. 도메인마다 가르치는 방식이 다른데, 진입 경험까지 제각각이면 학습자는 매번 새 프로그램을 배우게 됩니다. "공통 진입 + 도메인별 분기"가 이 프로젝트의 출발점이었습니다.

사용자는 하나의 메타버스 Lobby에서 그린에너지 · 반도체 · 스마트팩토리 중 하나로 분기합니다. 로비·아바타·이동 같은 뼈대는 세 도메인이 공유하기 때문에, 한 번 익힌 진입 방식이 다른 도메인에서도 그대로 통합니다.

분기 이후의 학습 방식은 도메인마다 다릅니다. 그린에너지는 설비를 직접 돌려보는 3D 회전 + 이론학습, 반도체는 패키징 단계를 짚는 3D 상호작용 + 이론학습, 스마트팩토리는 게임처럼 라인에 진입해 오더를 처리하는 OMS 시뮬레이션입니다. 같은 골격 위에서 도메인의 성격에 맞게 인터랙션 밀도를 다르게 가져갔습니다.

Primary Interface

그린에너지 3D 회전 학습

세 도메인 중 인터랙션의 양 끝을 보여주는 두 화면. 손으로 설비를 돌려보는 그린에너지 3D 학습과, 데이터로 라인을 운영하는 스마트팩토리 오더관리가 같은 플랫폼 위에서 얼마나 다른 밀도로 작동하는지가 이 프로젝트의 핵심입니다.

  • 3D 설비 뷰포트화면 중앙을 설비 자체에 내줌. 학습자가 드래그로 직접 돌려보며 구조를 파악하는, 이 도메인의 핵심 인터랙션.
  • 이론 패널 (좌)3D 조작과 이론 설명을 한 화면에 병치. 돌려보는 즉시 옆에서 무엇을 보는지 읽을 수 있게 좌측에 고정.
  • 회전 / 시점 컨트롤 (우)회전·확대·리셋을 우측에 모음. 3D 조작이 처음인 학습자도 버튼으로 같은 동작을 수행하도록 이중 경로 제공.
  • 단계 / 진행 바이론학습의 현재 위치를 하단에 고정. 3D에 몰입하다 길을 잃지 않도록 진행 맥락을 항상 노출.

Primary Interface

스마트팩토리 오더관리(OMS)

  • 오더 현황 헤더처리 중·대기·완료를 상단에 요약. 게임처럼 라인에 들어와 있지만, 무엇을 운영 중인지는 데이터로 먼저 인지하게 함.

/01—Overview

성격이 다른 네 가지 실험을 한 시뮬레이터 안에 담는 일. 시험마다 장비도 절차도 다르지만, 학습자가 매번 새 UI를 배우게 만들 수는 없었습니다. "공통 UI 베이스 + 시험별 분기"가 이 프로젝트의 뼈대입니다.

네 종 모두 좌상단 KOREATECH 로고 · 상단 단계 탭 · 우측 컨트롤(가이드북·조견표) · 하단 자막·페이지 카운터라는 동일한 골격을 공유합니다. 한 시험에서 익힌 화면 구조가 다른 시험에서도 그대로 통하기 때문에, 학습자는 절차에만 집중할 수 있습니다.

분기되는 것은 두 가지입니다. 하나는 컬러 시스템 — 인장(그린) · 경도(시안) · 어닐링/노멀라이징(블루) · 퀜칭/템퍼링(오렌지)으로 시험을 색으로 즉시 구분합니다. 다른 하나는 전용 실험 화면 — 만능재료시험기, 비커스 경도계 프로그램, 전기로·온도 컨트롤러, 퀜칭 수조처럼 각 시험의 실제 장비를 그대로 재현했습니다.

Primary Interface

인장시험 조건 설정 화면

시험의 양 끝을 보여주는 두 화면. 소프트웨어로 조건을 설정하는 인장시험과, 압흔을 측정해 경도를 산출하는 경도시험. 같은 베이스 위에서 입력 중심 화면과 측정 중심 화면이 어떻게 다른지가 핵심입니다.

  • 시험편 형상 선택KS B 0801 4호·13호 등 시험편 형상을 먼저 고르게 함. 조건 입력의 전제를 상단 우측에 고정해 흐름을 잡음.
  • 시료 폭 · 두께 입력단면적 산출에 쓰이는 핵심 수치. 입력 필드를 형상 선택 바로 아래 묶어 "고르고 → 채우는" 순서를 자연스럽게.
  • 조건 그래프 영역설정한 조건이 곡선으로 즉시 반영되는 좌측 대형 영역. 수치 입력의 결과를 시각으로 확인하게 함.
  • 조건 저장 / 초기화저장(그린)·초기화(레드)를 하단에 분리. 되돌리기와 확정의 색을 분명히 갈라 오조작을 방지.

Primary Interface

경도시험 압입자 확대기 (HB 산출)

  • HB 산출 공식"시험하중 ÷ 압입자 자국의 표면적". 측정 화면 위에 공식을 함께 띄워, 무엇을 왜 재는지 연결.
  • 압흔 단면 다이어그램시험편 표면에 생긴 압흔을 단면으로 시각화. 측정값이 어떤 기하에서 나오는지 직관적으로 보여줌.
  • d · h · D 치수 표기압입자국 지름(d)·깊이(h)·압입자 지름(D)을 다이어그램에 직접 라벨링해 변수 혼동을 줄임.
  • 측정 가이드 자막"자국의 면적을 기준으로 하중을 나누어 경도값(HB)을 계산"을 하단에 명시해 다음 행동을 안내.
